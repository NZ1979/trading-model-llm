# Deploy plan: Phase C (per-ticker PM RVOL thresholds)

**Target deploy window**: 06:30-07:00 MDT on 2026-05-07 (before 07:30 MDT market open).

## Deploy execution

### In a normal PowerShell window on your Windows machine

#### Step 1: scp the five files to the VPS

```powershell
cd C:\trading\trading-platform
scp main.py trader-prod:/opt/trader/app/main.py
scp analysis\indicators.py trader-prod:/opt/trader/app/analysis/indicators.py
scp data\pm_rvol_thresholds.py trader-prod:/opt/trader/app/data/pm_rvol_thresholds.py
scp scripts\build_pm_rvol_thresholds.py trader-prod:/opt/trader/app/scripts/build_pm_rvol_thresholds.py
scp tests\test_pm_rvol_thresholds.py trader-prod:/opt/trader/app/tests/test_pm_rvol_thresholds.py
```

Each `scp` should print one progress line ending `100%`.

#### Step 2: verify compile + ownership + restart in one ssh round-trip

```powershell
ssh trader-prod "cd /opt/trader/app && /opt/trader/.venv/bin/python -m py_compile main.py analysis/indicators.py data/pm_rvol_thresholds.py scripts/build_pm_rvol_thresholds.py tests/test_pm_rvol_thresholds.py && chown trader:trader main.py analysis/indicators.py data/pm_rvol_thresholds.py scripts/build_pm_rvol_thresholds.py tests/test_pm_rvol_thresholds.py && systemctl restart trader && sleep 3 && systemctl is-active trader"
```

Expected output: `active`

If this errors at any step, do NOT proceed. The most likely failure is import error from the new modules — check the error message, fix locally, re-scp the corrected file, retry.

#### Step 3: verify boot logs

Wait 10 seconds for boot routine to log, then:

```powershell
ssh trader-prod 'journalctl -u trader -n 30 --no-pager'
```

Expected lines (in approximate order):

- `Watchlist: 500 symbols (dynamic, from config/watchlist_dynamic.json)`
- `Loaded PM RVOL thresholds for 0 tickers from config/pm_rvol_thresholds.json (default=5.0, metadata={})` — first boot has no JSON file yet, this is correct
- OR `PM RVOL thresholds file not found at config/pm_rvol_thresholds.json; using hard fallback (5.0) for all tickers` — also correct first-boot behavior
- `Alpaca paper account equity: $...`
- `Finnhub client initialized`
- `Platform booted, watching 500 symbols`
- News WS authenticated, Alpaca bars WS authenticated and subscribed
- No `Traceback`, no `ERROR`, no `AttributeError`

If you see any Traceback, paste it and stop.

#### Step 4: trigger the threshold sweep manually (optional but recommended)

The scheduled sweep fires at 08:30 ET (06:30 MDT) — it's already past that time if you deploy at 06:30. Manually triggering ensures we have the JSON file in place before market open:

```powershell
ssh trader-prod "cd /opt/trader/app && /opt/trader/.venv/bin/python scripts/build_pm_rvol_thresholds.py"
```

Expected runtime: ~5 minutes (500 tickers, 10 concurrent Polygon calls, ~30s per batch).

Output:
- `Wrote PM RVOL thresholds for N tickers to config/pm_rvol_thresholds.json` (N should be close to 500)

If errors: paste them. Polygon rate limits may cause some tickers to fail (they'll be reported but not block the build).

#### Step 5: confirm the JSON file is in place and reload it into the running service

```powershell
ssh trader-prod 'wc -l /opt/trader/app/config/pm_rvol_thresholds.json && head -5 /opt/trader/app/config/pm_rvol_thresholds.json'
```

Should show ~503 lines (500 tickers + _default + _metadata + closing braces), with the first 5 lines showing the JSON header.

The running service won't see this file unless we either:
- (a) restart the service again (picks up the file at boot), OR
- (b) wait until the next scheduled refresh at tomorrow's 08:30 ET (it auto-reloads in-place)

Recommended: restart once more so today's signals at 09:35 ET use real per-ticker values:

```powershell
ssh trader-prod "systemctl restart trader && sleep 3 && systemctl is-active trader"
ssh trader-prod 'journalctl -u trader -n 10 --no-pager | grep "Loaded PM RVOL"'
```

The boot log line should now show `Loaded PM RVOL thresholds for ~500 tickers from ... (default=5.0, metadata={'computed_at':...})`.

## Rollback (if Phase C deploy goes wrong)

The five new files don't break the existing system if reverted — they're additive. To rollback:

```powershell
ssh trader-prod "cd /opt/trader/app && git checkout c1de1f0 -- main.py analysis/indicators.py && rm -f data/pm_rvol_thresholds.py scripts/build_pm_rvol_thresholds.py tests/test_pm_rvol_thresholds.py config/pm_rvol_thresholds.json && systemctl restart trader && sleep 3 && systemctl is-active trader"
```

This reverts main.py and indicators.py to the Bug H commit (c1de1f0), removes the Phase C files entirely, and restarts. Service is back to the pre-Phase-C state in ~10 seconds.
