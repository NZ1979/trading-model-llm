### What shipped

The replay-harness comparison report's § 5b, previously a stub that read "*per-decision regime label is not yet persisted*," now renders a real per-(regime, source) performance table populated from a new `replay_decisions.regime` column.

**Schema migration (3 parts, additive + idempotent):**

1. `regime TEXT` added to `_SCHEMA` so fresh DBs include it.
2. `_migrate_add_regime_column(conn)` — checks `PRAGMA table_info(replay_decisions)`, runs `ALTER TABLE ADD COLUMN regime TEXT` only when missing. Called from `init_replay_db` after `executescript(_SCHEMA)`. Idempotent: second-call no-op.
3. Existing DBs created before #22 get the column added on next open with NULL values for old rows. The report's NULL rendering (`*(none)*`) keeps legacy data visible without claiming a regime it doesn't have.

**Persistence write threading:**

- `write_day_results(..., regime: str | None = None)` — new kwarg, threaded into both `_write_portfolio_side` calls (LLM + base) and into the t3_only INSERT block. Default `None` preserves back-compat for pre-#22 callers.
- `_write_portfolio_side(..., regime: str | None = None)` — accepts the kwarg, adds `regime` to the live_merged/base INSERT column list + VALUES tuple.
- T3 INSERT in `write_day_results` includes `regime` directly.

**Driver wiring:**

- `_persist(day_result, *, regime=None)` — inner closure in `run_replay`, accepts the kwarg.
- Success path: `_persist(day_result, regime=day_state.market_regime_label)`.
- `run_day_ticks`-failure path: same (day_state exists by then).
- `build_day_state`-failure path: `_persist(skipped_result)` — no regime arg, defaults to None. `write_day_results` no-ops on skipped days anyway, so the value is informational.

### Section 5b in the report

```
## 5b. Regime-stratified performance

| Regime | Source | Trades | Win rate | Total realized P&L | Avg P&L |
|---|---|---|---|---|---|
| bear | live_merged | 1 | 0.0% | $-30.00 | $-30.00 |
| bull | live_merged | 1 | 100.0% | $50.00 | $50.00 |
| neutral | live_merged | 3 | 66.7% | $40.00 | $13.33 |
| *(none)* | live_merged | 1 | 100.0% | $50.00 | $50.00 |
```

SQL is a single GROUP BY (regime, decision_source) over `replay_fills` joined to `replay_decisions` on `decision_id`. NULL regimes sort last via `CASE WHEN regime IS NULL THEN 1 ELSE 0 END`. T3 is intentionally excluded (no fills → no realized P&L). Empty result → "*No closed positions to stratify*" placeholder.

The section ends with a note that per-regime max drawdown is omitted (drawdown is a continuous portfolio-curve metric; per-regime DD requires a regime column on `replay_equity_curve`, which is a separate sub-task).
