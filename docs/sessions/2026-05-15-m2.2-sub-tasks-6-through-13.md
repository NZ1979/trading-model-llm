## Sub-task #8: CachedLLMClient adapter

**SHA:** `f589040`

**Files touched:**
- `data/replay_cache.py` (new)
- `tests/test_replay_cache.py` (new, 25 tests)

**What shipped:**
`CachedLLMClient` adapter that satisfies the `strategy.llm.clients.LLMClient` Protocol. Wraps any tier backend (Anthropic, Qwen local, future Haiku stand-in) transparently with on-disk JSON caching. Cache key derived via the existing `data.replay.config.cache_key` helper: `<cache_dir>/<backend>/<model_id>/<sha256>.json` with the hash over `(prompt_version, canonical-JSON of LLMContext)`. `LLMContext` is a frozen dataclass (not Pydantic), so the canonical-JSON path goes through `dataclasses.asdict + json.dumps(sort_keys=True, default=str, separators=(",", ":"))`. `LLMDecision` IS Pydantic and round-trips via `model_dump_json` / `model_validate_json`. Asymmetry documented in the module docstring.

On-disk envelope `schema_version=1`: `{schema_version, cached_at, prompt_version, backend, model_id, decision: <LLMDecision JSON>}`. Forensic-debug metadata + the decision payload. `schema_version` mismatch → soft-miss with WARNING + overwrite.

Per-instance `hits` / `misses` counters for the run-summary report.

**Failure semantics:**
- Cache hit but malformed JSON / wrong schema / missing decision / LLMDecision validation failure → WARNING + miss + overwrite (forward-compat).
- Cache write OSError → WARNING + return inner result anyway (best-effort caching; never block a multi-hour replay over transient disk error).
- Inner client raises (`APIUnavailableError`, `SchemaInvalidError`, `BudgetExhaustedError`, generic) → propagate unchanged, no cache write. Errors are NEVER cached so a transient 5xx can't poison the cache for the next run.
- Empty `prompt_version` at construction → `ValueError` loud.

Atomic writes via `.tmp` + `os.replace` mirror the `historical_news` / `ticker_metadata` cache pattern.

**Tests covered:**
Construction (inner identity pass-through, empty prompt_version raises), cache miss path with envelope structure assertions, cache hit path with Pydantic round-trip equality, key invalidation across prompt_version/backend/model_id/context, canonical-JSON stability (identical contexts share cache slot), every soft-miss path with caplog verification, write failure with mocked `os.replace` OSError + `.tmp` cleanup, parametrized inner-exception propagation across the four typed errors, HF-style "meta-llama/Llama-3.3-70B" model_id sanitization, counter accuracy across mixed sequences, persistence across distinct wrapper instances pointing at the same cache_dir.

**Test helper note:** the async test runner uses `asyncio.run()` rather than the deprecated `asyncio.get_event_loop()` to stay clean under Python 3.10+.

## Sub-task #9: per-day data-prep orchestrator

**SHA:** `90c68fd`

**Files touched:**
- `data/replay/day_state.py` (new)
- `tests/test_day_state.py` (new, 33 tests)

**What shipped:**
`build_day_state(config, trading_date, tickers, market_ctx, sentiment_conn) -> DayState` is the seam where every loader from #1-#7 meets the (future) tick loop. One async call per trading day produces a frozen `DayState` containing per-ticker `TickerDayState` bundles plus day-level fields (`vix_level`, `market_regime_label`, `sentiment_lookup`, `failed_tickers`).

Per-ticker fan-out (bounded `asyncio.Semaphore`, default concurrency 8) loads in parallel per symbol:
- 25 cal days of 1-min bars (covers today's full session + 20 trading days of PM volume baseline).
- 220 cal days of daily bars (covers SMA-200 warmup).
- `ticker_metadata` as of `trading_date`.

Day-level synchronous compute derives `DailyContext` via `compute_daily_context` (sliced to bars before `trading_date`), `PremarketContext` via `compute_premarket_context` with locally-derived 20-trading-day PM volume baseline, and `last_5_daily_closes` from the trailing daily tail.

**Replay-aware PM volume baseline derivation:** `PolygonRESTClient.get_premarket_volume_history` uses `datetime.now()` and can't be made as-of-aware without touching a module shared with live. `_derive_pm_volume_history` instead filters the 25-cal-day minute frame to bars before `trading_date` in the PM window (04:00 ≤ ET hour < 09:30), groups by date, sums volume, returns the trailing 20 entries.

**Day-level batch news + sentiment:** one `load_historical_news` call for the union of surviving tickers over `[trading_date - 1d, trading_date]` (two-day window covers any sub-24h news lookback the tick loop applies). One `lookup_article_sentiments` call for the union of every surviving ticker's news items. `DayState.sentiment_lookup` carries the resulting dict at the day level (not duplicated per ticker on `TickerDayState`).

**Run-level inputs via MarketContextBundle:** `build_day_state` does NOT re-fetch SPY/VIX per day. The replay-loop driver loads them once at run start via `market_context.load_market_data` and passes the bundle through. `DayState.vix_level` resolves via `pd.Series.asof()` on the FRED VIXCLS frame (tz-aware UTC, query also tz-aware UTC). `DayState.market_regime_label` runs `compute_daily_context` on SPY's daily bars sliced through `trading_date - 1`; bull/bear/neutral/unknown via the 200 SMA 0.5% buffer.

**Failure semantics:**
- Per-ticker loader RuntimeError → drop ticker from `DayState.tickers` with WARNING, record failure mode in `DayState.failed_tickers`, continue. This is NOT the Rule-18 "silent zero-substitution" violation #6's news loader guards against — the LLM never sees that ticker that day at all.
- All tickers fail → `RuntimeError` loud (global outage signal).
- News batch failure → `RuntimeError` loud (universal input).
- SPY/VIX failure happens upstream in `load_market_data`.
- `DailyContext` / `PremarketContext` None → pass through; downstream context_builder + LLM prompt template handle None.

**Earnings flags:** `has_earnings_today` / `has_earnings_within_3d` hardcoded `False` with TODO. Historical earnings calendar is its own sub-task (Finnhub costs money; fixture would need its own export procedure).

**Schema collision refinement during implementation:** my proposal had `TickerDayState.spy_minute_bars` carrying a per-day SPY slice, but `MarketContextBundle` already owns run-level SPY/VIX. Refined to: `DayState` carries only per-day-resolved values; the tick loop slices `market_ctx.spy_5min` per tick. Eliminates 30 redundant SPY fetches on a 30-day replay.

**VIX tz bug caught during test run:** the initial `_resolve_vix_level` passed a tz-naive `pd.Timestamp(trading_date)` to `.asof()` against the tz-aware UTC index; pandas raised "Cannot compare tz-naive and tz-aware timestamps." Fixed by building the query as `pd.Timestamp(trading_date, tz="UTC")`. Three test failures caught the regression before commit; a source comment documents the tz reasoning.

## Sub-task #10: per-tick LLMContext slicing

**SHA:** `17bd0e9`

**Files touched:**
- `strategy/llm/context_builder.py` (modified — additive `last_5_daily_closes` kwarg)
- `data/replay/tick_context.py` (new)
- `tests/test_tick_context.py` (new, 46 tests)

**What shipped:**
`build_tick_context(*, day_state, market_ctx, config, ticker, tick_et, position=None, todays_prior_decisions=())` → `LLMContext`. Pure function. Slices the day's data to as-of, runs indicator computation, gates news visibility, derives the tick-time SPY and time-of-day fields, and dispatches to the shared `build_llm_context`.

Internal flow:
1. Slice `TickerDayState.minute_bars` to bars `<= tick_et` on `tick_et.date`.
2. Resample to 5-min via `pandas.DataFrame.resample("5min", label="left", closed="left", origin="start_day")` with `first/max/min/last/sum` for OHLCV+trade_count and a volume-weighted-mean for vwap.
3. Run `analysis.indicators.compute_intraday_indicators(rth_only=True)` for indicator columns.
4. Filter news via `filter_visible_at` with `lookback_hours=24` (LLM-context spec, separate from the 2h pre-filter window) and `lag_seconds=config.news_lag_seconds`.
5. Cap news at top-5 most-recent via `[-5:]` (news loader sorts ascending).
6. Convert via `items_to_context_dicts(visible_news, day_state.sentiment_lookup)`.
7. Slice `market_ctx.spy_5min` to bars on today at or before `tick_et`; compute `spy_change_pct = (last_close - first_open) / first_open * 100` and `spy_rvol = last_bar_volume / mean(spy_5min.volume.tail(20))` with 1.0 fallbacks on empty / zero baseline.
8. Compute `minutes_since_open` / `minutes_until_close` clamped `[0, 390]`. `in_gap_and_go_window = minutes_since_open <= 60`.
9. Dispatch to `build_llm_context` with `last_5_daily_closes=tds.last_5_daily_closes` and all derived kwargs.

**Tiny additive change to `strategy/llm/context_builder.build_llm_context`:** added `last_5_daily_closes: tuple[float, ...] = ()` kwarg, wired into the LLMContext constructor (replacing the line 217-224 stub block). Default empty preserves live + smoke tests + `test_context_builder.py` callers. `TickerDayState.last_5_daily_closes` from #9 now flows through to LLMContext.

**Choices documented in source:**
- `spy_rvol` uses simple 20-bar SMA matching per-ticker `volume_ratio_vs_20bar` convention (design-doc richer "cumulative since 09:30 vs 20d at same time of day" is a follow-up).
- News lookback hardcoded 24h per `LLMContext.news_items` field-comment spec (separate from the 2h pre-filter knob).
- News top-5 cap per same spec.
- `catalyst_flags` hardcoded `()` until a dedicated classifier lands.
- KeyError on missing ticker is a caller bug (tick loop iterates over `day_state.tickers.keys()` only).

## Sub-task #11: per-tick pre-filter

**SHA:** `12503d6`

**Files touched:**
- `data/replay/pre_filter.py` (new)
- `tests/test_pre_filter.py` (new, 29 tests)

**What shipped:**
`pre_filter_candidates(day_state, tick_et, currently_holding, config) -> tuple[str, ...]` matches the design doc's four-gate OR pseudocode at lines 175-191:
1. `pm_rvol >= config.pre_filter_min_pm_rvol` (default 2.0).
2. `abs(gap_pct) >= config.pre_filter_min_gap_pct` (default 1.0).
3. News visible at `tick_et` within `config.pre_filter_news_lookback_hours` (default 2h, separate from the LLM context's 24h window) after the `config.news_lag_seconds` ingestion buffer.
4. `ticker in currently_holding`.

Any one is sufficient (early-exit on first match). Hard cap at `config.max_candidates_per_tick` (default 30) with deterministic iteration order via Python dict insertion ordering. Iteration breaks early on cap to avoid scanning the tail.

**Defaults:** `PremarketContext` None → `pm_rvol=0.0` and `gap_pct=0.0` (fails both quantitative gates; news/holding can still rescue).

**Boundary quirks:**
- `failed_tickers` in `DayState` silently skipped (iteration is over `day_state.tickers`).
- `currently_holding` entry for a ticker absent from `day_state.tickers` silently ignored.
- Empty holding set OK.

**News-gate independence:** the 2h pre-filter window is SEPARATE from the LLM context's 24h `news_items` window. Same `filter_visible_at` helper, different `lookback_hours` arg.

**Design rationale documented:** the base codebase's signal engine evaluates every watchlist ticker every tick for the fair-comparison report, but the LLM path is gated through this pre-filter to keep replay cost bounded. "Miss for LLM, hit for base" cases will be tracked separately in the eventual report.

Per tick (sequential): derive `currently_holding` from `portfolio.positions` (open positions only), narrow via `pre_filter_candidates`, per survivor build LLMContext via `build_tick_context` with rolling per-ticker tail-5 `todays_prior_decisions` and the position dict from `SimulatedPortfolio.get_position`, `await signal_engine.evaluate` (never raises), append `TickDecision`, record the per-ticker prior_decision entry for the next tick.

**Sequential within-tick (not asyncio.gather):** chosen for simple `EscalationBudget` consumption ordering. Budget is consumed on ATTEMPT not on success; concurrent attempts can race past the cap. On a 30-day × 50-ticker first run this is the slow path (~hours), but CachedLLMClient from #8 collapses re-runs to milliseconds. Parallelization is a follow-up if measured first-run cost justifies the synchronization overhead.

**Explicitly out of scope:**
- Tier 3 (Opus) labeling — replay-only, separate flow with its own budget + sample rate.
- Fill simulation — `record_entry` / `record_exit` / `check_stops` / `mark_to_market`.
- Base-strategy parallel evaluation.
- Persistence.
- Within-tick parallelism.

Each is its own sub-task. `clients.t3` not read here; `portfolio` is read for holding-set + position dict but never mutated.

**Caller contract:** `budget.reset()` is the caller's responsibility per day. The loop intentionally does NOT reset the budget so a caller bug that shares one budget across days is detectable.

## Sub-task #13: multi-day driver

**SHA:** `e5a75c2`

**Files touched:**
- `data/replay/driver.py` (new)
- `tests/test_driver.py` (new, 20 tests)

**What shipped:**
`async run_replay(*, config, clients, sentiment_conn, portfolio=None) -> list[DayRunResult]` is the outer-loop function the CLI imports.

1. Resolves tickers via `config.tickers_tuple` (raises `NotImplementedError` on the `"watchlist"` literal — resolution via `data/watchlist_builder.py` is its own sub-task).
2. Loads `MarketContextBundle` once at run start via `load_market_data(config.start_date, config.end_date)`. SPY failure propagates loud.
3. Constructs `EscalationBudget(max_per_day=config.t2_max_per_day)` at run start.
4. Iterates trading days via `pandas.bdate_range(start=config.start_date, end=config.end_date)` (weekday filter).
5. Per day: `budget.reset()`, try `build_day_state` (catch RuntimeError → skipped), try `run_day_ticks` (defensive catch → skipped), append `DayRunResult`.
6. Returns ordered list with skipped days included.

**`DayRunResult`** frozen dataclass: `(trading_date, decisions, failed_tickers, t2_escalations_used, skipped, skip_reason)`. Distinguishes "skipped (data unavailable / per-day failure)" from "ran-and-produced-zero." `t2_escalations_used` is `budget.used` at end of day (0 for skipped days).

**Holiday handling:** weekday filter only. US trading holidays (Christmas, Thanksgiving) survive `bdate_range` and then fail `build_day_state` because Polygon returns empty bars; the per-day try/except converts them to skipped entries. A proper holiday calendar (`pandas_market_calendars` or static list) is a small follow-up sub-task.

**Failure semantics:**
- `load_market_data` failure at run start: propagates loud. Partial output without market context would mislead the report.
- Per-day `build_day_state` RuntimeError: catch, WARNING, skipped + continue. Lets a 30-day replay survive a single bad day (typically a US holiday on a weekday).
- Per-day `run_day_ticks` raising: shouldn't happen per #12's contract, but defensively wrapped + skipped + continue on programmer-bug cases.
- `failed_tickers` from `DayState` is preserved on the skipped result so the report can still surface it.

**Test helper bug caught during gate B:** `_tick_decisions` helper built timestamps via raw minute arithmetic (`30 + 5 * i`) which overflowed at `i=6` (60 minutes). Fixed to use `timedelta(minutes=5 * i)` from a base 09:30 datetime. Underscored the value of running the scoped gate before the full suite.
