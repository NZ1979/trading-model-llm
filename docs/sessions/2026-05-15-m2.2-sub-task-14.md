### What shipped

`apply_decisions_to_portfolio(*, decisions, day_state, portfolio, config, decision_id_start=1) -> FillSimulationResult` is the synchronous orchestrator that converts one day's `list[TickDecision]` (the output of `run_day_ticks`) into portfolio mutations. Pure-ish — mutates the supplied `SimulatedPortfolio` in place and returns a structured manifest of fills + rejections.

**Position-transition table (per design doc § Simulation):**

| Current | Decision | Action |
|---|---|---|
| flat | Buy | `record_entry` long |
| flat | Sell | `record_entry` short |
| flat | Hold | no-op |
| long | Buy | no-op |
| long | Sell | `record_exit` long (`exit_reason="flip"`), then `record_entry` short |
| long | Hold | no-op |
| short | Buy | `record_exit` short (`exit_reason="flip"`), then `record_entry` long |
| short | Sell | no-op |
| short | Hold | no-op |

**Per-entry-attempt flow:**

1. Resample `TickerDayState.minute_bars` to RTH 5-min bars once per ticker; cache in a local dict so multi-decision days on the same ticker don't re-resample.
2. Look up the current 5-min bar at `tick_et` and the next 5-min bar.
3. Pick the fill reference per `config.fill_at` (`next_bar_open` default, `current_close` optimistic).
4. Derive ATR-based stop pct via `compute_atr_stop_pct(entry_price, daily_atr=TickerDayState.daily_context.daily_atr_14)`. `compute_atr_stop_pct` handles `daily_context is None` and `daily_atr_14 == 0` via its own `fallback_pct=2.0`.
5. Size via `size_from_risk(equity=portfolio.equity({}), entry_price=ref, stop_loss_pct=stop_pct, risk_per_trade_pct=config.risk_per_trade_pct)`.
6. Risk-gate via `strategy.risk.validate_order` with `open_positions` converted from `sim.portfolio.Position` (unsigned qty + side) to `strategy.risk.Position` (signed qty + current_price = entry_price approximation until MTM lands).
7. `sim.fills.simulate_fill` to apply slippage and produce the `SimulatedFill`.
8. `portfolio.record_entry`.

**Flip semantics:** `record_exit` at the same fill reference as the entry would use (slippage applied to the EXIT side, opposite of the existing position's direction), with `exit_reason="flip"`. Both legs share the same fill timestamp. The exit is visible on `portfolio.closed_positions`; only the new entry shows in `FillSimulationResult.fills`.

**Structured rejections:** `RejectedEntry(tick_et, ticker, side, requested_qty, reason)` rows on `FillSimulationResult.rejections` for every Buy/Sell that didn't transact. Reasons enumerate: `no_5min_bars`, `no_5min_bar_at_tick`, `no_next_bar_for_fill`, `invalid_equity`, `size_from_risk_zero`, `position_cap_below_one_share`, `position_cap_exceeded ...`, `total_exposure_cap_exceeded ...`. Locked option B from the design proposal — the eventual comparison report counts rejections by reason without parsing logs (Rule 18 visible degradation, not silent drop).

**Decision IDs:** sequential int starting at `decision_id_start` (default 1), advancing per input `TickDecision` regardless of action (including Hold). The persistence sub-task will reconcile these with the `replay_decisions` table's primary key.

### Notable design decisions surfaced and locked

- **Module location:** `data/replay/fill_simulator.py` (sibling to `tick_loop.py` and `driver.py`) rather than `sim/`. The orchestration belongs in the replay namespace; `sim/fills.py` and `sim/portfolio.py` stay primitive.
- **Equity approximation for risk gate:** `portfolio.equity({})` marks all open positions at their entry price. The conservative "exposure-at-entry" view is exact in this sub-task because no exits happen between entries inside this function; once per-tick MTM lands the risk gate will see live equity.
- **`current_price` approximation in risk Position:** signed qty plus `current_price = entry_price`. Same MTM caveat applies.
- **Stop-pct passed both to `size_from_risk` AND `validate_order`:** keeps the ATR-derived stop consistent across sizing and the bracket-stop computation. Matches how `main.py` calls these in live.
- **5-min bar resampling:** filtered to RTH (09:30 inclusive, 16:00 exclusive) before resampling, so the 5-min frame's first index is 09:30 and last is 15:55. Pre/post-market 1-min bars are excluded from the fill bookkeeping.
- **Hold decisions advance `decision_id`:** input-list index maps cleanly to the eventual persistence-table primary key. Tradeoff: some IDs in `replay_fills` will have no fill row (the Hold ones), but the FK invariant holds.

## Next sub-task: #15 — stop-checking, EOD flatten, mark-to-market

**Recommended shape (proposed but not yet locked):**

A per-bar inner loop that runs alongside `apply_decisions_to_portfolio`. Architecturally there are two reasonable approaches:

**Option A: interleave bars with decisions inside the driver.** Per 5-min bar: call `portfolio.check_stops` against the bar's lows/highs; for each triggered stop, `record_exit` with `exit_reason="stop_hit"`. Then call `portfolio.mark_to_market` with the bar's close prices. Decisions at that tick get processed AFTER stops fire (so a Buy decision after a stop-out can re-enter on the same tick if the LLM said so). EOD flatten is a final pass at 15:55.

**Option B: separate per-bar driver function.** `apply_bar_to_portfolio(*, bar_et, day_state, portfolio, config)` does stops + MTM for one 5-min bar; the driver interleaves it with the decision-walker. Cleaner separation of "decision-driven mutations" vs "price-driven mutations", but two functions touching the same portfolio.

Recommendation: **option B**. Two single-responsibility functions are easier to test independently and match the design doc's mental model (stops are a price-driven trigger, not a decision-driven one).
