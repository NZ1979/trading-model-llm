### What shipped

Three new symbols in `data/replay/tick_loop.py`:

1. **`_build_today_5min_indicators(tds, trading_date) -> pd.DataFrame`** — resamples minute_bars to RTH 5-min and calls `compute_intraday_indicators` on the result. Cached per ticker per day in the loop so a single resample+indicator pass serves all 78 ticks for that ticker (key efficiency win: O(tickers) work rather than O(tickers × 78)). Indicators are backward-looking, so computing on the full day's frame and slicing later is equivalent to slicing then computing.

2. **`_trade_to_llm_decision(td: TradeDecision) -> LLMDecision`** — adapter that lets `apply_day_to_portfolio` consume base decisions without modification. Maps:
   - `action` → `action` (same enum).
   - `technical_confidence` → `confidence` (cast to int).
   - `setup` → `setup_label` (truncated to 50 chars per the pydantic `max_length=50`).
   - `reasons` → `reasoning` (joined with `"; "`, truncated to 280 chars per `max_length=280`).
   - Empty reasons tuple → `"no_reasons"` sentinel.
   - LLM-tier-only fields (`stop_loss_atr_multiple`, `take_profit_atr_multiple`, `time_horizon`, forward predictions) land at their pydantic defaults — the right "no-prediction" sentinels for the comparison report.

3. **`run_day_base_ticks(*, day_state, config, sentiment_conn, portfolio=None) -> list[TickDecision]`** — synchronous (no network I/O). For each of the 78 canonical 5-min ticks × every ticker in `day_state.tickers`:
   - Slice the indicator-augmented frame up to `tick_et` inclusive (point-in-time correct — no peeking).
   - `generate_signal(intraday_df, daily_ctx, premarket_ctx)` → `TechnicalSignal`.
   - `latest_sentiment(sentiment_conn, ticker, tick_et)` → `int | None` (1-hour freshness window, matches live).
   - `evaluate_trade(ticker, sentiment, technical_signal, futures_walls=None, require_walls_for_pullback=config.base_require_walls_for_pullback)` → `TradeDecision`. Walls always None in replay (Databento canceled, per PROJECT_BLUEPRINT § Vendor stack).
   - Adapt → `LLMDecision` → `TickDecision`, append.

   No pre-filter applied. Per design doc § Pre-filter: "the base codebase's signal engine evaluates ALL watchlist tickers every tick. To make the comparison fair, we run base evaluation on every ticker too — only the LLM evaluation is gated by the pre-filter."

### `run_replay` rewire

New optional kwarg `base_portfolio: SimulatedPortfolio | None = None`. When set, per non-skipped day after the LLM `apply_day_to_portfolio` call:

1. `base_decisions = run_day_base_ticks(day_state, config, sentiment_conn, portfolio=base_portfolio)`.
2. `base_day_app = apply_day_to_portfolio(decisions=base_decisions, day_state, portfolio=base_portfolio, config)`.
3. Populate the six `base_*` fields on `DayRunResult` from `base_day_app`.

The same `apply_day_to_portfolio` machinery drives both portfolios — stops, EOD flatten, MTM apply symmetrically. The decision_id sequences are independent per portfolio (each starts at 1 per day) because they index into different `decisions` / `base_decisions` lists.

The per-day log line was extended to show counts for both sides.

### `write_day_results` refactor + base side

Extracted a private `_write_portfolio_side(...)` that takes `decisions`, `rejections`, `equity_curve`, `portfolio`, plus `decision_source` and `portfolio_name` strings. `write_day_results` now calls it once for the LLM side (always; `decision_source='live_merged'`, `portfolio_name='llm'`) and once for the base side (when `base_portfolio` is supplied; `decision_source='base'`, `portfolio_name='base'`).

Both writes happen inside the same `with conn:` transaction — atomic per-day semantics. If the base-side write fails, the LLM side rolls back too. Schema unchanged: the values 'base' for `decision_source` and 'base' for `portfolio_name` were already implicit in the column definitions.
