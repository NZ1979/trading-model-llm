### What shipped

Four public functions in `data/replay/persistence.py`:

1. **`init_replay_db(path) -> sqlite3.Connection`** — opens read-write; applies the schema via `CREATE TABLE IF NOT EXISTS` for every table + index (idempotent across calls); enables `PRAGMA foreign_keys = ON`; raises `FileNotFoundError` on missing parent dir (Rule 18 loud); propagates `sqlite3.DatabaseError` on corrupt file via a `PRAGMA schema_version` probe.

2. **`start_run(conn, *, config, repo_sha=None) -> int`** — inserts a `replay_runs` row, returns the new `run_id` (auto-increment). `started_at` stamped at call time with UTC ISO 8601. `config_json` serializes the full `ReplayConfig` dataclass via `dataclasses.asdict` + `json.dumps(default=str)` so Path / date fields stringify cleanly; tickers tuple normalized to list for JSON canonicalization.

3. **`write_day_results(conn, *, run_id, day_result, llm_portfolio) -> None`** — writes one day's rows in a single `with conn:` transaction. No-op for skipped days (`day_result.skipped == True`). The writer:
   - Inserts each `TickDecision` into `replay_decisions` with `decision_source='live_merged'` (later sub-tasks add per-tier and base rows). Captures a per-day → global id map for the FK linkage.
   - Inserts each `RejectedEntry` into `replay_rejections` with its `decision_id` resolved through the map. Unmatched decision_ids (shouldn't happen but defensive) log WARNING and skip.
   - Iterates `llm_portfolio.closed_positions` filtered to `entry_timestamp.date() == trading_date`. Writes one `replay_fills` row per closed Position with entry + exit columns populated. Multi-day positions (entry on prior day) are skipped — they belong to the prior day's write call.
   - Iterates `llm_portfolio.positions` (open positions, if any) for the defensive non-flatten path. Writes one row with NULL exit columns.
   - Inserts each `EquityPoint` from `day_result.equity_curve` into `replay_equity_curve` with `portfolio_name='llm'`. The two-points-at-15:55 case (pre + post EOD flatten) is preserved via the table's autoincrement `id` ordinal.

4. **`complete_run(conn, *, run_id, summary_json=None) -> None`** — updates `completed_at` (UTC ISO 8601) and `summary_json`. Idempotent — second call overwrites.

### Schema (5 tables)

```sql
replay_runs(run_id PK, started_at, completed_at, config_json, repo_sha, summary_json)
replay_decisions(id PK, run_id FK, trading_date, tick_et, ticker,
                 decision_source, action, setup_label, confidence, reasoning,
                 raw_response, risk_check_result, tier_provenance)
replay_fills(id PK, run_id FK, decision_id FK, ticker, side, qty,
             fill_price, fill_timestamp, stop_price,
             exit_timestamp, exit_price, exit_reason, realized_pl)
replay_rejections(id PK, run_id FK, decision_id FK, ticker, side,
                  requested_qty, reason)
replay_equity_curve(id PK, run_id FK, portfolio_name, bar_et,
                    equity, cash, n_open_positions)
```

Three indexes: `(run_id, trading_date)` on decisions, `(run_id, ticker, tick_et)` on decisions, `(run_id, portfolio_name, bar_et)` on equity_curve, `(run_id)` on fills.

The original design doc's § Storage spec was extended to add `replay_rejections` (#14's `RejectedEntry` had no place to live) and `replay_equity_curve` (#15's per-bar MTM). Stop-outs and EOD exits do NOT get their own tables — they populate the existing `replay_fills` row's exit columns via the closed Position. The design doc's one-row-per-fill mental model held up under #15's new data shapes.

### `RejectedEntry.decision_id` schema bump

`RejectedEntry` gained a required `decision_id: int` field to support clean FK linkage to `replay_decisions.id`. Without it, the persistence layer would have had to match by `(tick_et, ticker)` — fragile if multiple decisions hit the same ticker at the same tick.

Wired through 6 construction sites in `fill_simulator.py` (each rejection in `_attempt_entry` and `_apply_one_decision` already had `decision_id` in scope as a kwarg). Two direct test constructions updated (one in `test_fill_simulator.py`, one in `test_driver.py`). No change to the `_apply_one_decision` return type.

### `ReplayConfig.replay_db_path` derived property

Single source of truth: `output_dir / "replay_results.db"`. Callers prepare the parent dir with `mkdir(parents=True, exist_ok=True)` before invoking `init_replay_db` (which itself does NOT mkdir — Rule 20: don't side-effect the filesystem from a function whose contract is "open the DB").

### `run_replay` rewire

New optional kwargs: `persistence_conn: sqlite3.Connection | None = None` and `run_id: int | None = None`. Pair-validation raises `ValueError` if exactly one is set (programmer-bug surface). A private `_persist(day_result)` closure encapsulates the per-day write call, called at all three `results.append` sites (the two skipped-day paths + the success path) for symmetry. The writer's own skipped-day no-op handles the semantics.

Persistence fires only when `persistence_enabled AND portfolio is not None` — fill data lives on the portfolio, so persisting without one would write decision rows only. That's a future feature; for #16 the wiring requires a portfolio.

### One subtle bug caught + fixed in-flight (Rule 14)

First PowerShell pytest run hit a **circular import**: `driver.py` imports `write_day_results` from `persistence.py`, but `persistence.py` originally imported `DayRunResult` from `driver.py` at module top-level. Python's import system blew up trying to resolve them.

Fix: gate the `DayRunResult` import in `persistence.py` behind `TYPE_CHECKING`. The module already has `from __future__ import annotations`, so the runtime never sees the type hint — the import is only needed for static analysis. One commit forward, zero behavior change, all 786 tests green.

The mistake was missed in pre-PowerShell py_compile because the bash sandbox couldn't load the new test files at all (Rule 24 mount-staleness on `historical_sentiment.py` caused pytest collection to abort before reaching the cycle). The first time the cycle ran was on Godzilla. Lesson: circular imports are an import-order failure, not a syntax failure — py_compile catches the latter but not the former. The verification gate that catches both is `python -c "import data.replay.driver, data.replay.persistence"`.
