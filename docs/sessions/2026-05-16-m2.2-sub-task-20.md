### What shipped

Tier 3 (Opus) labeling runs as a **distinct flow** from the live `evaluate` orchestration — `signal_engine.py` explicitly ignores `clients.t3` per its own docstring and `tick_loop.py::run_day_ticks` was deliberately scoped to T1+T2 only. #20 adds the parallel T3 pass.

**`data/replay/t3_budget.py`** — `T3Budget` dataclass:

```python
@dataclass
class T3Budget:
    cap_dollars: float
    per_call_estimate: float = 0.05
    used_dollars: float = 0.0
    n_calls: int = 0
    n_skipped_budget: int = 0
    n_skipped_sample: int = 0

    def has_capacity(self) -> bool:
        return self.used_dollars + self.per_call_estimate <= self.cap_dollars

    def record_call(self) -> None: ...
    def record_skip_budget(self) -> None: ...
    def record_skip_sample(self) -> None: ...
```

Default `per_call_estimate=0.05` is conservative vs the design doc's ~$0.003/call after caching. CLI flag `--t3-per-call-estimate` overrides for tuned values. Refining to actual post-call cost is deferred until the AnthropicClient exposes per-call usage.

**`_t3_should_sample(ticker, tick_et, sample_rate)`** — deterministic hash-based sampling:

```python
h = hashlib.sha256(f"{ticker}|{tick_et.isoformat()}".encode()).hexdigest()
return (int(h[:8], 16) / 0xFFFFFFFF) < sample_rate
```

Same (ticker, tick) always samples or doesn't at a given rate. Crucially, the sampling is **monotonic in rate**: candidates selected at rate=0.3 are a strict subset of those selected at rate=0.7. This means a prior `rate=1.0` cache is fully reusable on a `rate=0.5` follow-up — no cache miss for any sampled candidate.

**`run_day_t3_ticks(*, day_state, market_ctx, config, clients, budget, portfolio=None) -> list[TickDecision]`** — async, mirrors `run_day_ticks` shape exactly:

For each (tick, `pre_filter_candidates` survivor):
1. Sample-rate gate (cheap, hash-only). Miss → `budget.record_skip_sample()`, continue.
2. Budget gate. Exhausted → `budget.record_skip_budget()` + WARNING log, continue.
3. `build_tick_context(...)` — SAME LLMContext shape `run_day_ticks` builds, so T1↔T3 agreement metrics in the comparison report are apples-to-apples. T3 maintains its OWN prior-decisions history (not shared with T1's) — `t3_prior_history` is local.
4. `budget.record_call()` (BEFORE the API call; mirrors EscalationBudget's "consume on attempt, not success" pattern from `signal_engine.py`).
5. `await clients.t3.evaluate(ctx)`.
6. On success: tag the returned LLMDecision with `tier_provenance="t3_only"` via `model_copy(update=...)`.
7. On failure: synthetic Hold via `_make_t3_hold_failure` with `tier_provenance="t3_failed"` and one of three setup_labels (`schema_invalid_t3`, `api_failure_t3`, `t3_unexpected`). Failure detection by class name to avoid importing `strategy.llm.clients` (circular-import hazard).

Raises `ValueError` when `clients.t3 is None` — driver guards this; reaching it is a programmer bug.

### `run_replay` rewire

New optional kwarg `t3_budget: T3Budget | None = None`. Per non-skipped day:

```python
if clients.t3 is not None and t3_budget is not None:
    t3_decisions = await run_day_t3_ticks(
        day_state=day_state, market_ctx=market_ctx,
        config=config, clients=clients, budget=t3_budget,
        portfolio=portfolio,
    )
else:
    t3_decisions = []
```

Budget is caller-owned (mirrors `EscalationBudget` pattern) so summary stats are accessible after the run. The CLI constructs it once at run start and reads `n_calls / n_skipped_* / used_dollars` for `summary_json`.

Pre-#20 tests in the same file used MagicMock unimported (worked because they constructed via dataclasses), but the T3 tests needed explicit fake T3 client instances.
2. **Float precision in `test_budget_exhaustion_mid_run_records_skips`** — used `cap_dollars=0.15, per_call_estimate=0.05`, expecting 3 calls to fit exactly.
